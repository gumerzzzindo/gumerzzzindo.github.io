# Oletools - Guía de Referencia para Análisis de Malware Office

## Introducción

Oletools es una colección de herramientas Python orientadas al análisis forense y la detección de malware en documentos Microsoft Office. Permite inspeccionar archivos OLE, OpenXML, VBA, DDE, objetos incrustados y otros elementos comúnmente utilizados en campañas de phishing y malware.

---

# Herramientas Principales

## oleid.py

### Descripción

Realiza una identificación rápida de indicadores sospechosos en documentos Office.

### Funcionalidades

- Detecta macros VBA.
- Detecta objetos incrustados.
- Detecta plantillas remotas.
- Detecta cifrado.
- Detecta enlaces externos.

### Uso

```bash
oleid documento.docm
```

### Aplicación práctica

Primer paso durante el triage de documentos sospechosos.

---

## oledir.py

### Descripción

Muestra la estructura interna de un archivo OLE.

### Funcionalidades

- Lista streams y storages.
- Identifica módulos VBA.
- Localiza datos ocultos.

### Uso

```bash
oledir documento.doc
```

### Aplicación práctica

Identificación de módulos VBA y componentes incrustados.

---

## olevba.py

### Descripción

Herramienta principal para el análisis de macros VBA.

### Funcionalidades

- Extrae código VBA.
- Detecta AutoExec.
- Detecta funciones de ejecución automática.
- Identifica cadenas Base64.
- Analiza macros ofuscadas.
- Detecta indicadores de comportamiento malicioso.

### Uso

```bash
olevba documento.docm
```

### Opciones útiles

```bash
olevba --decode documento.docm
olevba --reveal documento.docm
olevba --json documento.docm
olevba --deobf documento.docm
```

### Indicadores detectados

- AutoOpen
- Document_Open
- Workbook_Open
- Shell
- CreateObject
- GetObject
- Base64
- URLs
- PowerShell
- WMI
- DLL Execution
- File Write Operations

### Aplicación práctica

Análisis de documentos utilizados por APT28, Emotet, Dridex, AgentTesla y otras familias de malware.

# Caso Práctico: Documento APT28

## Comportamiento observado

Durante el análisis con `olevba` se identificó:

- Función `AutoOpen()`.
- Decodificación de datos Base64.
- Extracción de payload desde XML interno.
- Escritura de un archivo en `%APPDATA%`.
- Ocultación del archivo generado.
- Ejecución mediante WMI.
- Lanzamiento de `rundll32.exe`.

## Indicadores detectados

| Tipo | Indicador |
|--------|------------|
| AutoExec | AutoOpen |
| Suspicious | CreateObject |
| Suspicious | GetObject |
| Suspicious | WMI |
| Suspicious | Base64 |
| Suspicious | File Write |
| Suspicious | Hidden File |
| Suspicious | rundll32.exe |

## Cadena de ejecución

```text
Documento Word
    ↓
AutoOpen()
    ↓
Extracción Base64 desde XML
    ↓
Decodificación DLL
    ↓
Guardado en %APPDATA%\user.dat
    ↓
Archivo oculto
    ↓
WMI Win32_Process.Create()
    ↓
rundll32.exe user.dat,#1
```

## Conclusión

La muestra utiliza macros VBA para desplegar y ejecutar una DLL almacenada dentro del propio documento. Este patrón es habitual en campañas de espionaje y malware avanzado, donde la carga útil se almacena codificada dentro del documento para evitar la detección.
